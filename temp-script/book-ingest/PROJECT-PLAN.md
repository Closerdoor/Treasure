# 书籍数据多源爬取工具设计方案

本文档记录书籍数据多源爬取工具的整体设计方案。

---

## 一、项目目标

为个人收藏馆网站（Treasure）实现一个多源书籍数据爬取工具，用于批量录入书籍数据。

**设计原则**：
- 复用电影爬虫的架构和配置
- 遵循 `docs/BROWSER-CONFIG.md` 的浏览器配置
- 多源并行，豆瓣为主，OpenLibrary 补充

---

## 二、数据来源

### 2.1 来源列表

| 来源 | 提供数据 | 优先级 | 爬取方式 |
|------|----------|--------|----------|
| 豆瓣读书 | 基本信息、评分、书评、封面、标签、系列 | 最高 | Playwright（浏览器模拟） |
| OpenLibrary | 英文信息、作者、封面、ISBN | 高 | REST API |
| 百度百科 | 作者简介、获奖信息 | 中 | Playwright（浏览器模拟） |
| Wikipedia | 获奖、经典语录 | 中 | REST API / Playwright |
| Goodreads | 英文评分、书评 | 低 | Playwright（后续实现） |

### 2.2 数据源选择理由

**豆瓣读书（主源）**：
- 中文书籍数据最全
- 评分体系成熟
- 用户书评丰富
- 与电影模块保持一致

**OpenLibrary（补充）**：
- 完全开放的 API
- 英文数据权威
- 作者信息完整
- ISBN 数据准确

---

## 三、约束条件

### 3.1 数据约束

| 约束项 | 要求 |
|--------|------|
| 书评数量 | 每源严格 20 条 |
| 书评排序 | 按热度排序（有用数/点赞数） |
| 封面下载 | 全部封面，原始分辨率 |
| 封面去重 | URL、文件名、内容哈希、跨来源四重去重 |

### 3.2 技术约束

| 约束项 | 要求 |
|--------|------|
| 工具位置 | `temp-script/book-ingest/` |
| 与现有 workflow 关系 | 完全独立，输出数据文件符合数据库字段设计 |
| 断点续传 | 必须支持 |
| 浏览器配置 | 必须遵循 `docs/BROWSER-CONFIG.md` |

### 3.3 冲突处理

| 处理方式 | 说明 |
|----------|------|
| 人工选择 | 生成 Markdown 审阅文件 |
| 审阅方式 | 半自动化（检测 Markdown 确认标记） |

## 五、数据存储结构

每本书生成一个独立目录：

```
temp-script/book-ingest/data/
├── 0201000001/                    # 书籍 ID（按规则生成）
│   ├── data.json                  # 合并后的完整数据（符合数据库字段设计）
│   ├── raw/                       # 原始数据（各来源独立存储）
│   │   ├── douban.json            # 豆瓣原始数据
│   │   ├── openlibrary.json       # OpenLibrary 原始数据
│   │   ├── baike.json             # 百度百科原始数据
│   │   └── wikipedia.json         # Wikipedia 原始数据
│   ├── images/                    # 下载的封面
│   │   ├── cover-main.jpg         # 主封面
│   │   ├── cover-002.jpg          # 补充封面
│   │   └── people/                # 作者头像
│   │       └── p000001-avatar.jpg
│   └── review.md                  # 审阅文件（有冲突时生成）
│
├── 0201000002/
│   └── ...
│
├── progress.json                  # 进度文件（断点续传）
└── errors.json                    # 错误记录
```

## 七、ID 生成规则

### 7.1 作品 ID

格式：`MMSSNNNNNN`

- `MM`：一级模块编号（02 = 书）
- `SS`：子模块编号（01 = 默认，暂不划分）
- `NNNNNN`：该子模块下的递增序号

示例：`0201000001` = 书/第 1 条

### 7.2 人物编码

格式：`p{NNNNNN}`

- `p`：固定前缀
- `NNNNNN`：6 位递增序号

示例：`p000001`

### 8.1 技术栈

| 组件 | 技术 |

## 九、断点续传机制

### 9.1 启动流程

1. 读取 `progress.json`
2. 检查 `status` 字段
3. 从 `in_progress` 的书籍继续
4. 从 `pending` 的书籍开始新爬取

### 9.2 状态流转

```
pending → in_progress → completed
                    ↓
                  error（记录到 errors.json）
```

## 十、错误处理

### 10.1 错误类型

| 错误类型 | 处理方式 |
|----------|----------|
| 网络错误 | 重试 3 次，间隔 5 秒 |
| 反爬封禁 | 暂停 10 分钟 |
| 数据缺失 | 记录到 errors.json，继续其他来源 |
| API 限流 | 等待限流解除后继续 |
| 找不到词条 | 记录到 errors.json，跳过该来源 |

---

## 十一、封面去重策略

### 11.1 去重维度

| 维度 | 检查时机 | 说明 |
|------|----------|------|
| URL | 下载前 | 相同 URL 直接跳过 |
| 文件名 | 下载前 | 相同文件名直接跳过 |
| 内容哈希 | 下载后 | 计算 MD5，相同跳过 |
| 跨来源 | 合并时 | 豆瓣和 OpenLibrary 同一封面只保留一份 |

---

## 十二、数据合并规则

### 12.1 字段优先级

| 字段 | 优先级 |
|------|--------|
| `title` | 豆瓣 > OpenLibrary |
| `original_title` | OpenLibrary > 豆瓣 |
| `year` | 豆瓣 > OpenLibrary |
| `synopsis_text` | 豆瓣 > OpenLibrary |
| `story_text`（作者简介） | Wikipedia > 百度百科 |
| 作者 | 豆瓣 > OpenLibrary |
| 评分 | 各来源独立存储 |

### 12.2 冲突检测

检测以下字段冲突：
- `year`（差异 > 1 年）
- `synopsis_text`（长度差异 > 50%）

冲突时生成 `review.md` 审阅文件。
