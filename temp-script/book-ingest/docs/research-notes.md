# 数据源调研笔记

本文档记录书籍数据源的调研分析，供开发参考。

---

## 一、全球书籍数据源

### 1. Goodreads

**地位**：全球最大的书籍分享与评论网站（现隶属于 Amazon）

**数据优势**：
- 书评质量极高，有详细的评分分布
- "读者也喜欢"功能强大，适合挖掘同类书籍
- 拥有高清的书籍封面图库

**爬取难度**：中高。API 权限收缩严重，需处理频率限制和反爬

### 2. OpenLibrary

**地位**：非营利性开放图书馆项目，目标是为每本书创建网页

**数据优势**：
- 完全开放的 RESTful API
- 可下载数据库 Dump 文件
- 数据字段规范（ISBN, LCCN 等）
- 有专门的封面服务 `covers.openlibrary.org`

**爬取难度**：低。API 友好，无需处理反爬

### 3. Google Books

**地位**：全球最庞大的数字图书索引

**数据优势**：
- 搜索精度高，几乎无遗漏
- API 强大，可获取作者、出版社、页数等
- 有时能获取书籍摘要或片段

**缺点**：用户评论相对 Goodreads 较少

### 4. LibraryThing

**地位**：偏向图书馆馆员、重度藏书家

**数据优势**：
- 标签系统极其细致
- 包含冷门书、珍本书信息

## 二、中文书籍数据源

### 1. 豆瓣读书

**地位**：中文书籍数据最全

**数据优势**：
- 中文书籍数据最全
- 评分体系成熟
- 用户书评丰富

**爬取方式**：Playwright 浏览器模拟

### 2. 当当网 / 京东

**数据优势**：
- 图书物理参数（纸张、装帧、开本）
- 价格信息
- 字数信息

### 3. 中国图书网

**数据优势**：
- 字数补充
- 出版社详情

---

## 三、网络小说数据源

### 1. 起点中文网

**地位**：中文网文的"发源地"和数据标杆

**数据优势**：
- 标签系统细致（第四天灾、克苏鲁风、凡人流等）
- 动态数据：字数、点击量、周推荐、荣誉徽章
- "本章说"和书评区数据密度高

**爬取难度**：高。有字体加密反爬机制

### 2. 优书网

**地位**：专门针对网文的第三方评价平台

**数据优势**：
- 毒草/仙草评价系统更客观
- 主题书单功能

**爬取难度**：相对友好

### 3. Novel Updates

**地位**：全球最大的亚洲网络小说翻译追踪站

**数据优势**：
- 关联中文原名、日文原名及各翻译版本
- 全球读者评价排行

### 4. Royal Road

**地位**：欧美最大的原创硬核网文社区

**数据优势**：
- 数据结构清晰
- 评论质量高

## 四、网文数据处理挑战

### 1. 封面质量参差不齐

很多网文封面是批量生成的"模板图"。

**建议**：为缺失高清封面的网文设计默认生成方案（如提取书名首字配合风格背景）

### 2. 状态频繁变动

网文是动态的，有连载中/完结状态。

**建议**：
- 爬虫记录 `Status` 字段
- 数据库预留"总字数"字段

### 3. 数据清洗

网文标题常带"营销号"后缀。

**建议**：用正则清洗掉"（精品推荐）"、"（新书火热连载）"等杂质

## 五、反爬虫技术方案

### 场景：起点字体混淆

起点等平台使用动态字体文件（.woff/.ttf），将数字或汉字替换为 Unicode 私有区字符（PUA）。

#### 方案一：动态字体解析（fontTools）

1. 抓包提取 CSS 中的字体文件 URL
2. 使用 `fontTools.ttLib.TTFont` 解析字形
3. 计算字形特征值（坐标序列 hash）
4. 建立乱码字符 → 真实文字的映射字典

**优点**：根本解决
**缺点**：实现复杂

#### 方案二：OCR 视觉识别

1. 使用 Playwright 加载页面，等待渲染完成
2. 定位混淆的 DOM 节点，局部截图
3. 送入 PaddleOCR 识别

**优点**：无视加密逻辑变化
**缺点**：速度较慢

**推荐**：初期用此方案跑通 MVP

#### 方案三：App API 抓取

1. 用 mitmproxy 代理手机网络
2. 抓取 App 的 API 请求（通常是明文 JSON）
3. 模拟移动端请求

**优点**：数据干净
**缺点**：需要逆向 API 签名规则

## 六、技术建议

### 1. 优先使用 API

对于 OpenLibrary、Google Books，直接调用 API 比 HTML 解析更稳健。

### 2. ISBN13 跨网站匹配

ISBN13 是最通用的书籍唯一标识符，可用于跨网站匹配更高清的封面。

### 3. 合规性

- 爬取前检查 `robots.txt`
- 设置合理的 `User-Agent` 和 `Crawl-Delay`
- 考虑使用现成的 Kaggle 数据集
