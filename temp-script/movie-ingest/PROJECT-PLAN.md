# 电影数据多源爬取工具设计方案

本文档记录电影数据多源爬取工具的整体设计方案。

---

## 一、项目目标

为个人收藏馆网站（Treasure）实现一个多源电影数据爬取工具，用于批量录入电影数据。

**第一批目标**：豆瓣 TOP250 电影

---

## 二、数据来源

共 7 个数据来源站点：

| 来源 | 提供数据 | 优先级 | 爬取方式 |
|------|----------|--------|----------|
| 豆瓣 | 基本信息、评分、短评、长评、图片、标签、相关推荐 | 最高 | Playwright（浏览器模拟） |
| TMDB | 基本信息、演职人员、图片、视频、原声、评分 | 高 | REST API |
| OMDb (IMDb) | 评分、分级、获奖信息 | 高 | REST API |
| 百度百科 | 基本信息补充、词条链接 | 中 | Playwright（浏览器模拟） |
| Wikipedia | 基本信息补充、获奖补充、名言名句、词条链接 | 中 | REST API / Playwright |
| 烂番茄 | 评分、评论 | 低 | Playwright（浏览器模拟） |
| Metacritic | 评分、评论 | 低 | Playwright（浏览器模拟） |

---

## 三、约束条件

### 3.1 数据约束

| 约束项 | 要求 |
|--------|------|
| 评论数量 | 每源严格 20 条 |
| 豆瓣评论 | 短评 20 条 + 长评 20 条 |
| 评论排序 | 按热度排序（有用数/点赞数） |
| 图片下载 | 全部图片，原始分辨率 |
| 图片去重 | URL、文件名、内容哈希、跨来源四重去重 |
| 人物头像 | TMDB 优先 |

### 3.2 技术约束

| 约束项 | 要求 |
|--------|------|
| 工具位置 | `temp-script/movie-ingest/` |
| 与现有 workflow 关系 | 完全独立，输出数据文件符合数据库字段设计 |
| 断点续传 | 必须支持 |
| 数据获取顺序 | 豆瓣优先 |
| 爬取速度 | 可接受较慢速度（烂番茄、Metacritic 有反爬） |

### 3.3 冲突处理

| 处理方式 | 说明 |
|----------|------|
| 人工选择 | 生成 Markdown 审阅文件 |
| 审阅方式 | 半自动化（检测 Markdown 确认标记） |

每部电影生成一个独立目录：

```

│   ├── data.json                  # 合并后的完整数据（符合数据库字段设计）
│   ├── raw/                       # 原始数据（各来源独立存储）
│   │   ├── douban.json            # 豆瓣原始数据
│   │   ├── tmdb.json              # TMDB 原始数据
│   │   ├── omdb.json              # OMDb 原始数据
│   │   ├── baike.json             # 百度百科原始数据

│   │   ├── poster-main.jpg        # 主海报

│   │   ├── still-01.jpg           # 剧照
```

## 九、断点续传机制

### 9.1 启动流程

1. 读取 `progress.json`
2. 检查 `status` 字段
3. 从 `in_progress` 的电影继续
4. 从 `pending` 的电影开始新爬取

### 9.2 状态流转

```
pending → in_progress → completed
                    ↓
                  error（记录到 errors.json）
```

### 9.3 来源状态

每个来源独立记录状态：
- `pending`：未开始
- `in_progress`：正在爬取
- `done`：已完成
- `error`：出错（记录错误信息）

## 十、错误处理

### 10.1 错误类型

| 错误类型 | 处理方式 |
|----------|----------|
| 网络错误 | 重试 3 次，间隔 5 秒 |
| 反爬封禁 | 暂停 10 分钟，更换 IP（如有） |
| 数据缺失 | 记录到 errors.json，继续其他来源 |
| API 限流 | 等待限流解除后继续 |
| 找不到词条 | 记录到 errors.json，跳过该来源 |

### 10.2 错误记录

`errors.json` 结构：

```json
[
  {
    "doubanId": "1292052",
```

## 十一、图片去重策略

### 11.1 去重维度

| 维度 | 检查时机 | 说明 |
|------|----------|------|
| URL | 下载前 | 相同 URL 直接跳过 |
| 文件名 | 下载前 | 相同文件名直接跳过 |
| 内容哈希 | 下载后 | 计算 MD5，相同跳过 |
| 跨来源 | 合并时 | 豆瓣和 TMDB 同一图片只保留一份 |

### 11.2 去重流程

```
URL 检查 → 文件名检查 → 下载 → MD5 计算 → 哈希检查 → 存储/跳过
```

## 十二、数据合并规则

### 12.1 字段优先级

| 字段 | 优先级 |
|------|--------|
| `title` | 豆瓣 > TMDB |
| `original_title` | TMDB > 豆瓣 |
| `year` | 豆瓣 > TMDB |
| `runtime_minutes` | 豆瓣 > TMDB |
| `synopsis_text` | 豆瓣 > 百度百科 |
| `story_text` | 豆瓣 > 百度百科 |
| 演职人员 | TMDB > 豆瓣 |
| 人物头像 | TMDB > 豆瓣 |
| 图片 | 豆瓣主海报 > TMDB 补充海报/剧照 |
| 评分 | 各来源独立存储 |

### 12.2 冲突检测

检测以下字段冲突：
- `runtime_minutes`（差异 > 5 分钟）
- `year`（差异 > 1 年）
- `synopsis_text`（长度差异 > 50%）
- `story_text`（长度差异 > 50%）

冲突时生成 `review.md` 审阅文件。

## 十五、ID 生成规则

### 15.1 作品 ID

格式：`MMSSNNNNNN`

- `MM`：一级模块编号（01-04）
- `SS`：子模块编号（01-05）
- `NNNNNN`：该子模块下的递增序号

示例：`0101000001` = 影视/电影/第 1 条

### 15.2 人物编码

格式：`p{NNNNNN}`

- `p`：固定前缀
- `NNNNNN`：6 位递增序号

示例：`p000098`

### 15.3 词项编码

格式：
- 类型：`g{NNNNNN}`
- 标签：`t{NNNNNN}`
