# Docs Maintenance

> Purpose: 说明 Treasure 项目文档如何维护，避免文档再次和真实项目状态脱节。
> Status: active
> Scope: 文档职责、更新触发条件、过期文档处理、状态记录规则
> Out of scope: 具体业务字段说明、UI 样式细节、脚本实现细节
> Update triggers: 文档体系变化、主流程变化、项目阶段变化
> Priority: 1

## 基本原则

- 文档必须优先记录当前事实，而不是历史愿望。
- 当前事实必须尽量量化。
- 旧结论如果仍有参考价值，应归档或标注历史状态。
- 不要让 `temp-script/` 中的实验说明覆盖 `docs/` 主文档。
- 当代码、数据库、generated、资源校验结果发生变化时，应同步更新对应文档。

## 文档职责

### `README.md`

文档入口和阅读顺序。

更新触发：

- 新增或废弃主文档。
- 文档职责发生变化。

### `PROJECT.md`

项目定位和阶段目标。

更新触发：

- V1 范围变化。
- 模块优先级变化。
- 项目从样板阶段进入新阶段。

### `STATUS.md`

当前真实状态。

更新触发：

- 数据库数量变化。
- generated 数量变化。
- 构建状态变化。
- 发布前校验结果变化。
- 新增阻塞风险或已解决重要风险。

状态汇报必须量化，例如：

```text
电影总数：250
generated 详情：250
主海报存在：249/250
人物头像存在：9072/12999，约 69.8%
```

### `ARCHITECTURE.md`

系统边界、模块边界和数据层级。

更新触发：

- 数据主源变化。
- 前台读取方式变化。
- 目录结构职责变化。
- 新模块正式接入。

### `WORKFLOW.md`

可重复执行的工作流。

更新触发：

- 导入、导出、资源同步、构建命令变化。
- 发布前校验流程变化。
- 临时脚本沉淀为稳定脚本。

### `GENERATED-DATA.md`

generated 契约和资源路径。

更新触发：

- `generated/` 目录结构变化。
- 前台消费字段变化。
- 图片/头像路径策略变化。
- 资源校验发现新的结构性问题。

### `DATABASE.md`

数据库表结构和当前数据量。

更新触发：

- Prisma schema 变化。
- 数据表新增、删除、重命名。
- 关键记录数量变化。
- 新模块表正式投入使用。

### `CONTRACTS.md`

内容字段语义和页面消费契约。

更新触发：

- 字段语义变化。
- 前台页面使用字段变化。
- 评分、图片、人物、分类、关联作品等契约变化。

### `UI-GUIDE.md`

前台视觉和交互规范。

更新触发：

- 页面结构变化。
- 主题策略变化。
- 列表页/详情页/首页主要 UI 模式变化。

## 历史文档处理

当文档不再代表当前状态时，优先执行以下其中一种：

1. 更新为当前状态。
2. 移动到 `docs/archive/{date}-{topic}/`。
3. 在文档顶部明确标注“历史参考，不作为当前规范”。

不要让两份文档同时宣称自己是同一事项的当前规范。

## 会话结束前检查

如果本轮工作改变了以下任一内容，应检查文档是否要更新：

- 数据库 schema
- 数据库记录量
- generated 目录结构
- 前台路由
- 构建命令
- 资源目录策略
- 发布前校验结果
- 模块优先级
- V1 范围

## 禁止事项

- 不要只写“已完成”，必须写完成量和总量。
- 不要把临时限制隐藏在脚本里。
- 不要把一次性调试发现写成长期规范。
- 不要让文档长期保留明显过期的统计数字。
