# 个人收藏馆设计文档 09：当前产品共识

## 1. 文档目的

本文档用于记录当前已经确认的产品设计共识，避免后续讨论时遗忘、回退或混入旧方案。

说明：

- 本文档记录的是当前阶段的已确认结论
- 若旧文档中的说法与本文档冲突，以本文档为准
- 后续继续讨论第 11 部分及实现方案时，应以本文档作为共同前提

## 2. 项目定位

当前项目定位已经明确为：

- 这是一个静态资料展示站点
- 不是博客站点
- 不是笔记站点
- 前台不以 Markdown 正文展示为核心
- 前台以结构化作品信息展示为核心

## 3. 前台与审阅材料边界

当前已确认：

- 每一部作品都有自己的 `data.json`
- 每一部作品也可能有对应的审阅用 `md` 文档
- 前台页面不直接展示这些 `md` 文档
- `md` 文档只用于人工审阅、查看、对照与后续归档
- 前台详情页正式数据来源是该作品自己的 `data.json`

## 4. 站点页面结构

站点整体固定为三层结构：

```text
首页 -> 模块列表页 -> 详情页
```

说明：

- 首页是站点入口与内容预览页
- 模块列表页负责某一模块下内容的统一浏览
- 详情页负责单部作品的完整展示

## 5. 模块范围

当前站点共有四个模块：

- 影视
- 书
- 游戏
- 音乐

当前原则：

- 四个模块列表页不要求完全通用
- 可以根据模块特征分别设计
- 当前优先推进影视模块

## 6. 首页共识

### 6.1 首页定位

首页不是纯导航页，也不是纯内容门户，而是两者之间的混合页。

首页承担的职责：

- 建立站点气质
- 作为四大模块总入口
- 提供各模块内容预览
- 将用户分发到模块列表页和详情页

### 6.2 首页结构

首页当前结构方向为：

1. 顶部导航
2. 首屏 Hero 区
3. 影视模块预览区
4. 书模块预览区
5. 游戏模块预览区
6. 音乐模块预览区
7. 页脚

### 6.3 首页首屏包含内容

首页首屏当前确认包含：

- 站点标题
- 一句简介 / 副标题
- 主题切换按钮
- 全站搜索入口 UI
- 一组精选海报 / 背景视觉
- 一个主入口按钮，例如“进入影视”
- 少量精选作品直达入口

### 6.4 首页模块区结构

每个模块区当前确认包含：

- 模块标题
- Tab 切换
- `查看更多`
- 1 到 2 行作品预览

### 6.5 首页模块区卡片

首页模块区若展示作品，固定使用网格卡片。

说明：

- 即使用列表页中的卡片视图样式
- 可以与列表页网格卡片一模一样
- 不需要额外单独设计首页专用卡片体系

### 6.6 首页模块区交互

当前交互已经确认：

- `Hover` Tab：切换当前预览内容
- `Click` Tab：跳转到对应模块列表页
- 点击 `查看更多`：跳转到对应模块列表页
- 点击作品卡片：进入对应详情页

## 7. 搜索共识

搜索当前已确认如下：

- 首页顶部搜索属于全站搜索
- 模块列表页内的搜索属于当前模块内搜索
- 搜索结果未来应落到独立搜索结果页
- 当前阶段先保留搜索入口 UI
- 当前阶段暂不实现搜索能力
- 等首页、列表页、详情页主干界面稳定后，再实现搜索

## 8. 影视模块列表页共识

### 8.1 默认状态

影视模块列表页当前确认：

- 默认展示影视模块下全部内容
- 不默认只看电影
- 如果从首页点击进入时携带筛选条件，则自动激活相应筛选条件

### 8.2 列表页功能

当前已确认模块列表页具备：

- 搜索入口 UI
- 筛选
- 分页
- 点击作品进入详情页

### 8.3 列表页筛选项

影视列表页当前确认的筛选项包括：

- 搜索
- 子模块：电影 / 电视剧 / 纪录片 / 动漫 / ...
- 类型：如 喜剧 / 动作 / 科幻 / ...
- 地区：如 美国 / 日本 / 韩国 / 中国大陆
- 年份
- 标签

### 8.4 列表页排序

当前已确认：

- V1 暂不开放用户手动排序切换
- 列表默认按上映时间排序

### 8.5 列表页布局

当前已确认：

- 影视模块列表页支持两种布局切换
- 即：
  - 网格布局
  - 列表布局

说明：

- 两种布局都应支持深色 / 浅色主题
- 布局切换不改变筛选结果本身

## 9. 电影详情页共识

### 9.1 详情页总体结构

电影详情页采用左右结构：

- 左侧为电影主体内容
- 右侧为关联内容

### 9.2 详情页头部

详情页头部的内容组织方式可以参考豆瓣电影，但 UI 需要优化，不照搬。

当前已确认：

- 顶部不会展示全量资料
- 顶部只展示一部分最重要的信息
- 主演在顶部只展示几位主角信息
- 顶部主演以文字方式展示

### 9.3 详情页头部字段方向

顶部基础信息区当前希望尽量覆盖现有 `md` 文档中的基础字段，例如：

- 中文标题
- 原名
- 年份
- 海报
- 导演
- 编剧
- 主演（仅前几位）
- 类型
- 制片国家 / 地区
- 语言
- 上映日期
- 片长
- 又名
- IMDb 编号
- 豆瓣评分与评价人数
- MPAA 分级
- 获奖信息

### 9.4 评分展示

详情页顶部当前确认：

- 显示一个主综合评分
- 同时展示四个平台原始评分摘要

当前评分来源为：

- 豆瓣
- IMDb
- TMDB
- 烂番茄

### 9.5 详情页 Tab

当前已确认详情页下方 Tab 包括：

1. 详情介绍
2. 演职员
3. 精彩影评
4. 视频
5. 图片
6. 音乐
7. 外部来源

### 9.6 演职员展示

当前已确认：

- 顶部只展示少量主角文字信息
- 完整人物展示下沉到 `演职员` Tab
- `演职员` Tab 采用：
  - 人物图片
  - 姓名
  - 职位 / 饰演角色

### 9.7 精彩影评展示

当前已确认：

- `精彩影评` Tab 直接展示较完整内容
- 不是只展示摘要
- 外链如果有，只作为补充
- 数据来源必须优先使用长评页，不再默认使用短评页

### 9.8 视频展示

当前已确认：

- `视频` Tab 只展示视频封面、标题、来源
- 点击跳转到外部页面
- 不做站内播放器

### 9.9 图片展示

当前已确认：

- `图片` Tab 使用统一图片流展示
- 不分成两个大分区单独展示“海报 / 剧照”
- 如有需要，仅通过轻量信息标识类型

### 9.10 外部来源展示

当前已确认：

- `外部来源` Tab 使用简洁链接列表
- 只展示站点名 + 跳转链接
- 暂不展示复杂来源溯源说明

### 9.11 右栏内容

当前已确认电影详情页右栏包括：

- 系列作品
- 相似作品

规则：

- 若该电影没有系列作品，则去掉系列作品模块
- 相似作品放在系列作品下方
- 二者都支持点击跳转到对应详情页

### 9.12 评论区

当前已确认：

- Giscus 评论区保留在详情页中展示
- 首页和列表页不展示评论区

## 10. 评分共识

当前已确认：

- V1 前台不额外展示馆长评分
- 当前前台评分以外部平台聚合结果为主
- 主评分为豆瓣 / IMDb / TMDB / 烂番茄四方评分的综合平均值
- 在合适位置可以同时展示四个平台原始评分

## 11. 类型与标签共识

当前已经明确：

- `类型` 与 `标签` 是两回事

### 11.1 类型

- 类型来自外部平台的相对标准化分类
- 例如：喜剧 / 动作 / 科幻 / 剧情

### 11.2 标签

- 标签同时包含两类来源：
  - 外部平台已有标签
  - 手动维护的站内标签

### 11.3 标签筛选

当前已确认：

- 列表页筛选 UI 中不区分标签来源
- 所有标签统一混合成一个标签集合供用户筛选

## 12. 主题共识

当前已确认：

- V1 正式支持深色 / 浅色主题切换
- 两套主题都必须成立，不是简单反色
- 当前主题切换效果可参考现有 `movie-list-card.html` 的思路

## 13. 数据分层共识

这一部分是当前讨论中非常关键的结论。

### 13.1 作品级数据

每部作品有自己独立的一份全量 `data.json`。

这份 `data.json`：

- 只放这部作品本身的结构化数据
- 是该作品的完整原始数据来源
- 不应塞入与该作品无关的站点级信息

### 13.2 页面聚合数据

首页和列表页展示作品时，可能只用到每个作品 `data.json` 中的一部分字段。

说明：

- 页面可以只提取自己需要的字段
- 不要求首页 / 列表页直接使用作品全量数据
- 更合理的方式是由多个作品数据派生出页面摘要数据或索引数据

### 13.3 站点级数据

以下内容属于站点级设计，不应写入每一部作品的 `data.json`：

- 首页首屏内容
- 模块顺序
- 首页 Tab 展示策略
- 全站导航信息
- 主题相关全局配置
- 搜索页规则
- 其它与单部作品无关的页面设计内容

## 14. 当前下一步前提

后续继续讨论时，应以以下前提为基础：

- 当前主干页面方向已经基本确认
- 当前最重要的数据边界已经确认
- 第 11 部分将继续讨论“作品级 `data.json` 应该长成什么样”
- 后续字段设计应严格区分：
  - 作品级数据
  - 页面聚合数据
  - 站点级配置

## 15. 电影录入工作流约束

当前项目中已经存在一套完整的电影录入工作流：`movie-entry-workflow`。

这套工作流的核心职责包括：

- 从多个电影数据源爬取数据
- 合并生成单部作品的 `data.json`
- 根据 `data.json` 一一对应生成审阅用 `md` 文档
- 维护 `source.json`、图片资源与相关原始材料

因此，后续关于电影 `data.json` 的任何字段规划，都必须遵守以下约束：

- `data.json` 不是孤立的前端接口文件，而是录入工作流的核心产物
- 若修改 `data.json` 的字段命名、字段结构或字段语义，必须同步评估并修改：
  - 录入脚本
  - 数据合并逻辑
  - `data.json -> index.md` 映射规则
  - 审阅用 `md` 模板
- 后续字段规范应优先追求：
  - 与现有工作流兼容
  - 最小必要修改
  - 便于未来批量录入几百部作品

当前阶段的默认策略应为：

- 先承认现有 `movie-entry-workflow` 已形成的事实标准
- 非必要不大改 `data.json` 顶层结构
- 优先做字段边界澄清与少量结构统一，而不是推翻重来
