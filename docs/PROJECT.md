## 项目定位

Treasure 是一个“精选型个人收藏馆”网站，用于收录影视、书、音乐、游戏等内容。

当前已确认：

- 这不是全量资料库，而是馆长筛选站点。
- 这不是博客或笔记站点。
- 前台以结构化资料展示为核心，而不是 Markdown 长文展示。
- 当前阶段不强调馆长评分或馆长评论作为前台主内容。

## 当前阶段目标

当前阶段的目标不是立刻做完整站点，而是先把影视模块中的“电影样板闭环”落地出来，并把首页、列表页、详情页的基础结构稳定下来。

这包含三件事：

- 落地前台页面结构与核心交互
- 明确作品级数据模型与录入规则
- 用少量真实电影条目验证 workflow、数据结构与前台展示链路可行

当前阶段结论：

- 首页、影视列表页、电影详情页已完成第一轮实现
- 首页后续会在内容量增加后再继续优化
- 列表页与详情页当前的信息结构已基本确定，后续只做细节微调
- 下一阶段更适合转向内容扩充、数据管理与导出链路整理

## 当前已确认的大方向

### 前台方向

- 展示站点采用 Astro 静态生成方案
- 计划部署到 GitHub Pages
- 核心内容浏览主链路为：`首页 -> 模块列表页 -> 详情页`
- 站点还包含辅助页面，如 `About` 与未来独立搜索结果页
- 当前优先推进影视模块，尤其是电影详情页与影视列表页
- 首页已完成首轮样板落地，但不作为当前优先细抠对象
- 列表页与详情页已进入稳定态，可作为后续内容扩充的承载骨架

### 内容方向

- 当前电影模块已经切换到“SQLite 作为结构化主源，generated JSON 作为前台输入”的链路
- `.local/staging/*.json` 当前只是过渡输入层，不再是前台正式数据来源
- `index.md` / 审阅用 Markdown 如保留，也只用于人工审阅、对照与归档
- 前台当前消费 `generated/*.json`，不直接读取旧作品目录文件

### 评分方向

- V1 主评分为豆瓣 / IMDb / TMDB / 烂番茄四方评分的综合平均值
- 前台不额外展示馆长评分作为主评分

### 主题方向

- V1 正式支持深色 / 浅色双主题
- 不是简单反色，而是两套都成立的正式体验

## V1 范围

当前 V1 以前台样板闭环为主，优先包含：

- 首页
- 影视模块列表页
- 电影详情页
- 关于页
- 基于当前已录入电影数据的静态展示能力

当前先保留、暂不实现：

- 全站搜索功能本身（仅保留入口 UI）
- 书 / 音乐 / 游戏模块的完整页面实现
- 馆长评分体系
- 复杂的个性化推荐或用户系统

补充说明：

- V1 首页仍保留四个模块预览区的整体结构
- 其中影视模块优先承载真实内容预览与跳转链路
- 书 / 音乐 / 游戏模块在 V1 阶段可以先作为弱化入口或占位预览存在，不要求同步完成完整模块实现

## 当前不做的事

当前明确不做：

- 不把前台做成博客式 Markdown 站点
- 不因为前端页面需求而把站点级信息塞进单个作品输入 JSON
- 不在 schema 尚未稳定前过早扩展到所有模块

## 待确认 / 延后决策

以下内容保留到后续阶段再确认：

- 书 / 音乐 / 游戏模块的具体页面结构
- 搜索结果页的最终形态与实现方式
- 其它模块详情页是否完全沿用电影页的 Tab 结构
- 未来是否增加站内标签体系之外的更多策展层能力
- 电影模块之外的其它模块何时全面迁移到本地数据库，并以导出产物驱动静态站点
