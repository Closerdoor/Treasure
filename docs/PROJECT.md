## 项目定位

Treasure 是一个“精选型个人收藏馆”网站，用于收录影视、书籍、音乐、游戏等作品。

核心定位：

- 它不是全量资料库。
- 它不是博客或长评站。
- 它是馆长筛选后的结构化收藏站。
- 前台以目录浏览、结构化信息、作品封面/海报视觉为核心。
- 本地内容工坊负责数据抓取、清洗、补全和确认。

## 当前阶段目标

当前阶段目标是稳定 DB-first 静态站闭环：

```text
SQLite -> generated JSON -> Astro -> GitHub Pages
```

当前不急于继续扩展大量新爬虫，而是优先确保：

- 数据库可以稳定导出 generated。
- generated 与数据库保持一致。
- 前台构建只依赖 generated 和 public assets。
- 发布前可以量化检查数据与资源覆盖率。
- 文档能快速说明当前真实状态。

## 当前 V1 范围

V1 以影视/电影为样板，优先包含：

- 首页
- 影视列表页
- 电影详情页
- 关于页
- 搜索入口页
- 数据库到静态站的导出/构建闭环

V1 可以暂缓：

- 完整站内搜索
- 书籍/音乐/游戏完整页面
- 用户系统
- 馆长评分体系
- 复杂推荐系统

## 当前已确认方向

### 数据方向

- SQLite 是本地结构化主源。
- Astro 不直接读取 SQLite。
- `generated/` 是前台数据投影。
- `site/public/assets/` 是前台发布资源目录。
- `.local/assets/` 是本地私有资源源目录。

### 前台方向

- 使用 Astro 静态生成。
- 部署到 GitHub Pages。
- 主题风格为资料馆/档案馆气质。
- 电影列表和详情页已经是当前最稳定的前台样板。

### 文档方向

- `docs/` 是当前规范来源。
- `temp-script/` 中的说明仅代表实验阶段上下文。
- 文档要优先记录当前事实和量化结果。

## 当前不做的事

- 不把前台做成 Markdown 博客。
- 不让线上站点依赖数据库或爬虫运行时。
- 不在 generated 契约未定前贸然扩展多个模块页面。
- 不把所有临时脚本直接纳入正式工作流。
- 不用未标注限制的脚本做批量数据决策。

## 后续关键决策
