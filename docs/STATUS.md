## 当前未完成

- 还没有稳定的 generated 完整性校验脚本。
- 电影资源仍有已知缺口。
- `generated.images` 中本地文件名和外链对象的边界需要统一。
- 书籍模块已有数据库草稿，但尚未进入 generated 和 Astro 页面链路。
- `temp-script/` 中仍有大量实验脚本、日志、调试产物，需要逐步分类归档。

## 下一步建议

优先级从高到低：

1. 新增 `tools/db/check-generated-integrity.mjs`，把当前手动校验固化为脚本。
2. 明确 `images.posters/stills` 是否只允许本地文件名字符串。
3. 决定人物头像缺失的处理策略：下载补齐、导出时只引用存在文件，或前台统一回退占位图。
4. 修正电影资源缺口后重新导出和构建。
5. 设计书籍模块的 generated 契约，再接入书籍页面。
6. 分类整理 `temp-script/`，把稳定脚本迁入 `tools/`。

## 风险

- 如果没有自动校验脚本，generated 与数据库可能再次悄悄脱节。
- 如果图片字段继续混用本地文件名和外链对象，前台画廊路径会变得不可靠。
- 如果书籍模块在 generated 契约稳定前直接做页面，后续容易返工。
- 如果旧文档继续保留过期数字，会误导后续执行者对项目状态的判断。
